## 1. 개요

기존 배포 가정은 **Vercel 서버리스**(함수 250MB 한도, matplotlib 제외, DB는 SQLite/Supabase 전환형)였다. 인계받은 물리/가상 서버로 **자체호스팅 단일 오리진** 구조로 이전했다.

핵심 전환점:
- **단일 프로세스 서빙**: 앱은 이미 `SPAStaticFiles`로 `/api/*`(FastAPI) + `frontend/dist`(SPA 폴백)를 한 포트에서 서빙하도록 설계됨 → nginx 1개 + uvicorn 1개로 단순화.
- **DB는 PostgreSQL**로 확정(`DATABASE_URL` 한 줄 전환).
- **Vercel 250MB 제한 소멸** → 단, matplotlib는 사용자 선호(“별로임”)에 따라 **미설치**, 리포트 차트는 PIL 경로 사용.
- 프론트는 **로컬 빌드 → 업로드**(서버에 Node 미설치).

- `https://…/api/…`       → FastAPI 라우터 (없으면 404, index 폴백 안 함)
- `http://…`              → 301 → `https://…`

## 4. 구성요소 상세

### 4.1 Python 3.11 (python-build-standalone)
- 위치: `/opt/python311/bin/python3` (= 3.11.15). 시스템 `python3.8`은 numpy 2.2/pandas 2.2 요구버전 미달이라 사용 불가.
- **deadsnakes PPA가 이 서버 네트워크에서 차단**(§7 참조)되어, github 릴리스의 portable CPython(install_only tar)을 `/opt/python311`에 전개.
- 앱 venv: `/opt/kweather/backend/.venv` (위 Python으로 생성).

### 4.2 PostgreSQL 12
- 설치: `apt install postgresql postgresql-contrib` (ubuntu archive).
- DB/Role:
  ```sql
  CREATE ROLE kweather LOGIN PASSWORD '<hex32>';
  CREATE DATABASE kweather OWNER kweather;
  ```
- 접속: `postgresql+psycopg2://kweather:<PW>@localhost:5432/kweather` (TCP md5).
- `listen_addresses = localhost` → **외부 미노출**. `pg_hba.conf`:
  ```
  local  all  postgres  peer
  local  all  all       peer
  host   all  all  127.0.0.1/32  md5
  host   all  all  ::1/128       md5
  ```
- 비번은 `/opt/kweather/backend/.env`(600)의 `DATABASE_URL`에만 존재. (배포 시 로컬 임시파일은 shred 처리.)

### 4.3 애플리케이션 배포 (디렉터리)
```
/opt/kweather/                 (hduser 소유)
├── backend/
│   ├── app/                   FastAPI (main, routers, services/report.py, fonts/NanumGothic)
│   ├── api/  vercel.json      ← Vercel 잔재(미사용, 무해)
│   ├── .venv/                 Python 3.11 venv
│   ├── .env                   운영 환경변수 (600)
│   ├── requirements.txt       (matplotlib 제외 = 운영)
│   ├── seed.py                데모 시드 스크립트
│   └── exports/               리포트 임시 출력 (쓰기 가능)
├── frontend/dist/             로컬 빌드 산출물 (SPA, main.py가 서빙)
└── sample_data/DEMO-*/        seed.py가 생성한 샘플 TXT
```
- **불변식**: `backend/`와 `frontend/dist/`는 형제여야 함 (main.py가 `<repo>/frontend/dist`를 찾음).
- 업로드 방식: backend = `rsync`, dist = **tar+scp**(openrsync 이슈, §7).

### 4.4 환경변수 `/opt/kweather/backend/.env` (600)
```ini
DATABASE_URL=postgresql+psycopg2://kweather:<REDACTED>@localhost:5432/kweather
WEATHER_PROVIDER=mock
ADMIN_EMAILS=cmlee@kweather.co.kr

# --- 실데이터 전환용(값은 사용자 ENV 수립 예정) ---
# WEATHER_PROVIDER=kweather
# KW_API_KEY=
# KW_BASE_URL=https://gateway.kweather.co.kr:8443/weather/w3/v2/kw-sensors
# KW_PAST_BASE_URL=https://gateway.kweather.co.kr:8443/weather/w4/v2
# KMA_API_KEY=
# KAKAO_REST_KEY=
```
- pydantic-settings가 `backend/.env`를 직접 로드 + systemd `EnvironmentFile`로도 주입(이중 안전).

### 4.5 systemd 서비스 `/etc/systemd/system/kweather.service`
```ini
[Unit]
Description=KW-DASHBOARD (FastAPI API + SPA)
After=network.target postgresql.service
Wants=postgresql.service

[Service]
Type=simple
User=hduser
Group=hduser
WorkingDirectory=/opt/kweather/backend
EnvironmentFile=/opt/kweather/backend/.env
ExecStart=/opt/kweather/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 4
Restart=always
RestartSec=3
TimeoutStopSec=20
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```
- `enabled`(부팅 자동), 4 workers(메모리 ~600MB). nginx·postgresql도 `enabled`.

### 4.6 nginx + TLS `/etc/nginx/sites-available/kweather`
```nginx
server {
    server_name sts.kweather.co.kr;
    client_max_body_size 50m;                 # 센서 TXT 업로드 대용량
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 120s;
        proxy_connect_timeout 10s;
    }
    listen [::]:443 ssl ipv6only=on;          # managed by Certbot
    listen 443 ssl;                           # managed by Certbot
    ssl_certificate     /etc/letsencrypt/live/sts.kweather.co.kr/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/sts.kweather.co.kr/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}
server {                                       # managed by Certbot — HTTP→HTTPS
    if ($host = sts.kweather.co.kr) { return 301 https://$host$request_uri; }
    listen 80; listen [::]:80;
    server_name sts.kweather.co.kr;
    return 404;
}
```
- 발급: `certbot --nginx -d sts.kweather.co.kr --redirect` (HTTP-01). 인증서 `/etc/letsencrypt/live/sts.kweather.co.kr/`.
- 갱신: `certbot.timer` enabled, `certbot renew --dry-run` 성공 확인.

## 5. 운영 가이드

### 5.1 상태 / 로그 / 제어
```bash
sudo systemctl status kweather          # 상태
journalctl -u kweather -f               # 실시간 로그
sudo systemctl restart kweather         # 재시작 (설정/코드 반영)
curl https://sts.kweather.co.kr/api/health
```

### 5.2 앱 업데이트 절차
```bash
# (1) 프론트 변경 시 — 로컬에서 빌드 후 dist 교체 (tar+scp 권장)
cd frontend && npm run build
tar czf /tmp/dist.tgz -C dist .
scp /tmp/dist.tgz kweather-sts:/tmp/
ssh kweather-sts 'rm -rf /opt/kweather/frontend/dist && mkdir -p /opt/kweather/frontend/dist \
  && tar xzf /tmp/dist.tgz -C /opt/kweather/frontend/dist && rm /tmp/dist.tgz'

# (2) 백엔드 변경 시 — rsync (.venv/.env/db 제외)
rsync -a --delete --exclude '.venv' --exclude '__pycache__' --exclude '*.pyc' \
  --exclude '*.db' --exclude 'exports' --exclude '.env' \
  backend/ kweather-sts:/opt/kweather/backend/

# (3) 의존성 변경 시
ssh kweather-sts '/opt/kweather/backend/.venv/bin/pip install -r /opt/kweather/backend/requirements.txt'

# (4) 반영
ssh kweather-sts 'sudo systemctl restart kweather'
```

### 5.3 DB 백업 / 복구
```bash
# 백업
ssh kweather-sts 'sudo -u postgres pg_dump kweather | gzip' > kweather_$(date +%F).sql.gz
# 복구
gunzip -c kweather_YYYY-MM-DD.sql.gz | ssh kweather-sts 'sudo -u postgres psql kweather'
```

### 5.4 인증서 갱신
- 자동(certbot.timer). 수동: `sudo certbot renew && sudo systemctl reload nginx`.

## 6. 보안 태세
- DB: localhost 전용(listen_addresses=localhost), TCP md5. 외부 접근 불가.
- `.env` 600(hduser). DB 비번은 .env에만, 배포 임시파일은 shred.
- 서비스: `User=hduser`, `NoNewPrivileges=true`. uvicorn은 127.0.0.1 바인딩(외부는 nginx만).
- TLS: Let's Encrypt + certbot 권장 ssl 옵션(options-ssl-nginx.conf, dhparams).
- CORS: allow-all이나 단일 오리진이라 사실상 무의미(운영 도메인 제한은 선택 개선).
- **개선 후보**: UFW 활성화(22/80/443만 허용), fail2ban, SSH 비번 로그인 비활성(키 전용), CORS 도메인 제한.

## 7. 트러블슈팅 / 함정 (재현 주의)

1. **deadsnakes PPA 차단** — 이 서버 네트워크가 `ppa.launchpad.net`의 InRelease는 받지만 **Packages 인덱스(대용량 GET)를 못 받음**(archive.ubuntu.com·pypi·github은 정상). 증상: `apt install python3.11` → “Unable to locate package”, GPG/에러 없음, 리스트에 InRelease만.
   → **해결**: deadsnakes 포기, **python-build-standalone**(github install_only tar)을 `/opt/python311`에 전개. URL의 `+`가 `%2B`로 인코딩됨에 유의.
2. **macOS openrsync(proto29) dist 전송 실패** — `rsync … frontend/dist/` 가 `unexpected end of file` 후 **exit 0인데 0바이트 전송**. backend rsync는 정상.
   → **해결**: dist는 **tar + scp + 원격 untar**.
3. **비대화 sudo** — ssh 비대화 셸엔 TTY 없음. `sshpass` 미설치 → 초기엔 `expect`, 키 인증 후엔 `printf PW | ssh … "sudo -S -p '' …"`(비번 stdin only).
4. **차트 글리프** — PIL 폰트(NanumGothic)에 `℃`(U+2103)·`▾` 없음(공백). 코드에서 `°C`/`▼` 사용(리포트 정본 참조). 운영=PIL 경로(matplotlib 미설치).

## 10. 재구축 절차 (from scratch, 요약)
1. 시스템: `apt install postgresql postgresql-contrib nginx certbot python3-certbot-nginx rsync` (ubuntu archive). Python은 python-build-standalone → `/opt/python311`.
2. DB: role/db `kweather` 생성 + 비번.
3. 앱: `/opt/kweather`(hduser) 생성, backend rsync + dist tar/scp. venv 생성 + `pip install -r requirements.txt`. `.env` 작성(600).
4. DB 초기화: `init_db`(앱 기동 시 자동) + 필요 시 `seed.py`.
5. 서비스: `kweather.service` 배치 → `daemon-reload` → `enable --now`.
6. nginx: site 배치 → `nginx -t` → reload → `certbot --nginx -d sts.kweather.co.kr --redirect`.
