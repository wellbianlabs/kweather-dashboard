## 1. 그리드 시스템 & 브레이크포인트

### 1.1 브레이크포인트 (Mantine 기본 계승)
| 토큰 | 폭 | 주 디바이스 | 네비 형태 |
| --- | --- | --- | --- |
| `base` | <576 | 모바일 세로 | 하단 탭바 + 드로어 |
| `sm` | ≥576 (36em) | 모바일 가로/소형 태블릿 | 하단 탭바 |
| `md` | ≥768 (48em) | 태블릿 | 사이드바(아이콘, 접힘) |
| `lg` | ≥992 (62em) | 노트북 | 사이드바(펼침) |
| `xl` | ≥1200 (75em) | 데스크톱 | 사이드바(펼침) + 넓은 컨텐츠 |

> 네비 전환 임계: **≥md(768) 사이드바 / <md 하단 탭바**. 사이드바는 ≥lg 펼침, md 구간 아이콘 접힘(오버레이 확장).

### 1.2 컨텐츠 그리드
- **12 컬럼**, 거터: `lg+` 24px / `sm~md` 20px / `base` 16px.
- 컨텐츠 최대폭: **1440px**(centered), 좌우 패딩 24/20/16.
- 수직 리듬: 섹션 간격 24(`lg`)/20/16. 카드 내부 패딩 24/20/16.
- 컬럼 스팬 규칙(공통): `lg`=12col 자유, `md`=주로 6/6·12, `sm·base`=12(1열 스택).

## 2. AppShell (전역 레이아웃 구조)

### 2.1 해부도 (데스크톱 ≥lg)
```
┌──────────────────────────────────────────────────────────────────┐ ← Header  h=60
│ [☰] 로고   |  기기▾  기준일자▾  기간▾ (컨텍스트 바)     ◑테마  계정▾ │
├───────────┬──────────────────────────────────────────────────────┤
│  Navbar    │                                                      │
│  w=248     │   Main (컨텐츠 그리드, max 1440, 패딩 24)              │
│ (펼침)     │                                                      │
│ ◼ 대시보드  │   ┌─────────── 12-col grid ──────────────────────┐   │
│ ◻ 위험지도  │   │                                              │   │
│ ◻ 리포트   │   │                                              │   │
│ ◻ 기기      │   └──────────────────────────────────────────────┘   │
│ ◻ 설정      │                                                      │
│ ──────     │                                                      │
│ ◻ 관리자▸  │                                                      │
│ [접기 «]    │                                                      │
└───────────┴──────────────────────────────────────────────────────┘
```
- Header 고정(sticky), 높이 60. 로고+네비토글 좌측 / 컨텍스트 필터 중앙 / 테마·계정 우측.
- Navbar: 펼침 248px / 접힘 **72px(아이콘 전용)**. 사용자가 토글, 상태 기억(localStorage).
- 관리자 진입 시 Navbar 컨텍스트가 운영 메뉴로 스왑(또는 별도 그룹).

### 2.2 태블릿 (md 768~991)
- Navbar 기본 **아이콘 접힘(72)**. 호버/탭 시 오버레이로 펼침(컨텐츠 밀지 않음).
- 컨텍스트 바는 헤더에서 한 줄 유지하되 라벨 축약.

### 2.3 모바일 (<md)
```
┌───────────────────────────────┐ ← Header h=56
│ [≡] 로고            ◑  계정 │
│ 기기▾  기준일자▾   (필터칩/시트) │
├───────────────────────────────┤
│                               │
│   Main (1열 스택, 패딩 16)      │
│                               │
│                               │
├───────────────────────────────┤ ← Bottom Tab h=56 (fixed)
│  ◼대시보드  ◻지도  ◻리포트  ◻더보기 │
└───────────────────────────────┘
```
- 사이드바 → **하단 탭바 4탭**(대시보드·지도·리포트·더보기). 부가(기기·설정·관리자)는 "더보기" 드로어.
- 컨텍스트 필터(기기/일자/기간)는 헤더 아래 **칩** → 탭 시 **바텀시트**.

### 2.4 Mantine 구현 매핑
```tsx
<AppShell
  header={{ height: 60 }}
  navbar={{ width: 248, breakpoint: 'md',
            collapsed: { mobile: !drawerOpen, desktop: collapsed } }}
  padding="md"
>
  <AppShell.Header>… 로고 · 컨텍스트바 · 테마/계정 …</AppShell.Header>
  <AppShell.Navbar>… NavLink 목록 …</AppShell.Navbar>
  <AppShell.Main><Container size={1440}>{라우트 화면}</Container></AppShell.Main>
</AppShell>
// 모바일 하단 탭바는 AppShell.Footer 또는 별도 fixed 컴포넌트로(미디어쿼리로 노출)
```

## 3. 화면별 레이아웃

### 3.1 대시보드
**데스크톱 (≥lg) — 12-col**
```
Row1: ┌ RiskHero  (col 1–8) ───────────┐ ┌ 현재 외부날씨 (9–12) ┐
      └──────────────────────────────────┘ └────────────────────┘
Row2: [KPI 1–3][KPI 4–6][KPI 7–9][KPI 10–12]   ← KPI 타일 4개 (각 span3)
Row3: ┌ 시계열 분석 (1–12, 임계선) ────────────────────────────┐
      └──────────────────────────────────────────────────────────┘
Row4: ┌ 내·외부 비교 (1–7) ─────────┐ ┌ 위험지도 미니 (8–12) ──┐
      └────────────────────────────┘ └────────────────────────┘
Row5: ┌ 폭염 단계별 안전조치 (1–12, 현재단계 강조) ───────────────┐
      └──────────────────────────────────────────────────────────┘
```
**태블릿 (md)**: RiskHero 12 / 현재날씨 12(또는 7·5) → KPI **2×2** → 차트 12 → 비교 12 → 지도 12 → 가이드 12.
**모바일 (<md)**: 전부 1열 스택, KPI는 2열(2×2) 유지. 순서 = 위험 우선:
```
RiskHero → 현재날씨 → KPI(2×2) → 시계열 → 비교 → 지도미니 → 안전조치
```

### 3.2 위험 지도
**데스크톱**: 좌 리스트(col 1–4: 사업장/기기·현재단계) + 우 지도(5–12). 선택 동기화.
```
┌ 사업장 리스트 (1–4) ┐ ┌ Leaflet 지도 (5–12) · 단계색 마커/클러스터 ┐
│ ● 데모제강 위험 38 │ │                                          │
│ ● 데모물류 주의 33 │ │           [지도]      [팝업: 기기·체감·시각] │
└────────────────────┘ └──────────────────────────────────────────┘
```
**모바일**: 지도 풀스크린 + 하단 **시트**(리스트/선택 상세). 단계 필터는 상단 칩.

### 3.3 리포트
**데스크톱**: 좌 조건(1–4: 기기·일자·기간·생성버튼) + 우 미리보기(5–12: 일일 보고서).
**모바일**: 조건(상단 카드) → 미리보기(하단). 생성 중 = 풀스크린 모달.

### 3.4 기기·사업장
**데스크톱**: 등록 폼(상단, 3-col 필드 그리드) + 관리 **테이블**(하단, 스크롤).
**모바일**: 폼 1열 → 관리 목록은 **테이블→카드 변환**(기기명·회사·주소·좌표·편집/삭제).

### 3.5 관리자
**데스크톱**: KPI 5타일(1행) → 추이 차트(12) → 테넌트 테이블(12) → 로그 테이블(12).
**모바일**: KPI 2×N → 차트(가로 스크롤) → 테이블→카드.

### 3.6 온보딩 / 인증
- 인증: 중앙 카드(max 420), 풀하이트, 배경 브랜드 톤. (AppShell 미적용)
- 온보딩(무데이터): **Stepper 상단 고정** + 단계 컨텐츠 중앙(max 720). 운영 모드 진입 시 AppShell로 전환.

## 4. 반응형 거동 요약 (레이아웃 상태표)

| 영역 | base/sm (<768) | md (768–991) | lg/xl (≥992) |
| --- | --- | --- | --- |
| 1차 네비 | 하단 탭바 + 드로어 | 사이드바(아이콘 72) | 사이드바(펼침 248) |
| 컨텍스트 필터 | 칩→바텀시트 | 헤더 1줄(축약) | 헤더 1줄(풀) |
| 대시보드 그리드 | 1열(KPI 2열) | 6/6·2×2 | 12-col 풀 |
| 테이블 | 카드 변환 | 가로 스크롤 | 풀 테이블 |
| 지도 | 풀스크린+시트 | 분할(4/8) | 분할(4/8) |
| 모달/필터 | 바텀시트 | 센터 모달 | 센터 모달 |

## 5. 구현 매핑 (Mantine)

- **셸**: `AppShell`(header/navbar/main) + 모바일 하단 탭(`AppShell.Footer` 또는 fixed). `navbar.breakpoint='md'`.
- **그리드**: 12-col은 `Grid`/`Grid.Col span={{ base:12, md:6, lg:8 }}`. 균등 카드는 `SimpleGrid cols={{ base:1, sm:2, lg:4 }}`.
- **컨테이너**: `Container size={1440}` (또는 테마 커스텀 size). 패딩=AppShell `padding="md"` + Container.
- **반응형 표시**: `visibleFrom`/`hiddenFrom`로 사이드바↔탭바 스왑.
- **테이블→카드**: md 미만에서 `Table` 숨기고 `Card` 리스트 렌더(`hiddenFrom="md"`/`visibleFrom="md"`).
- **상태 영속**: 네비 접힘·테마는 localStorage. 화면 전환은 라우팅(react-router)로 URL 매핑.

## 6. 미해결/의존 (레이아웃 관점)
1. **라우팅 도입**(react-router) — AppShell 네비가 URL과 연동되려면 선행. (기획서 §12)
2. **컨텐츠 최대폭 1280 vs 1440** — 데이터 밀집 대시보드는 1440 권장, 확정 필요.
3. **하단 탭 4 vs 5탭** — 대시보드·지도·리포트·더보기(4) 권장 / 기기 포함 5탭 대안.
4. 리브랜딩 컨셉(§4) 확정 시 표면·보더·헤더/네비 톤(특히 다크) 최종 수치 확정.

*— 본 레이아웃 설계는 기획서의 IA/화면 방향을 그리드·AppShell·반응형 수치까지 구체화한 실행 스펙이다.*
